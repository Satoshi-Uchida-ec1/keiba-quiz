# ロードマップと未決事項

## MVP

**ゴール**：友人に見せて「面白い、また使う」と言われる状態。

- 機能：M-01〜M-14（`features.md`）
- コンテンツ：7ジャンル × 3難易度 × 各10問 ＝ **210問**、解説記事10本
- 収益：なし
- 画像・音：なし

問題数の根拠は、全ジャンルミックスなら1セット10問として同じ問題に当たらずに約20セット遊べる量。
これを下回ると「同じ問題ばかり出る」という既存アプリへの典型的な不満を自分で再現してしまう。

ただし絞り込むと候補は少ない。1ジャンルなら30問（3セット分）、1ジャンル×1難易度なら10問（1セット分）しかない。
そのため候補が足りないときは隣の難易度などから補充する（`data-schema.md` の出題アルゴリズム手順1）。

### 着手前にやること

### 完了条件

- [ ] 初回訪問から1問目までのタップ数が2以下
- [ ] 全問に解説がある
- [ ] 間違えた問題が次のセッションで再出題される
- [ ] スマホ実機で片手操作が完結する
- [ ] 210問すべてに `source` が入っている
- [ ] M-01〜M-14 をすべて満たしている

### 実装順序の推奨

1. 問題データのスキーマ＋サンプル問題10問
2. 出題画面（P-04 / P-05）だけを動くコンポーネントとして
3. セッション管理と出題アルゴリズム
4. 結果画面・復習機能
5. 成績画面
6. ジャンル選択・トップページ
7. 解説記事の仕組み

## フェーズ2

**ゴール**：継続利用とトラフィックを作る。

- 機能：S-01〜S-09
- コンテンツ：500〜700問、解説記事20本
- 収益：投げ銭リンク（S-09）を導入。**公開前にホスティング規約を確認**（`monetization.md`）
- 優先順位：デイリーチャレンジ → 結果シェア → PWA → アカウント制 → 適応型出題

デイリーチャレンジと結果シェアを先に置くのは、実装コストが低いわりに獲得効果が大きいため。
「全員が同じ問題を解く → 結果をネタバレなしでシェアできる」構造は、
リアルタイム対戦なしで競争性を成立させる。

## 判断が変わる閾値

| 指標 | 閾値 | 取るアクション |
| --- | --- | --- |
| 問題数 | 5,000問超 | 静的JSONからDBへ移行を検討 |
| 1問あたりの回答データ | 各問数十回答 | 手動難易度タグからElo自動調整へ移行 |
| 投げ銭リンクの公開 | 公開前 | Vercel規約を確認。商用扱いならPro化か、Cloudflare Pages等へ移行 |
| 誤答通報 | 同一問題に複数件 | 即レビュー・修正 |
| 実測正答率 | 想定レンジから大きく外れる | その問題の難易度タグを修正 |
