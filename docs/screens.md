## 出題画面（P-04 / P-05）の設計要件

最も重要な画面。ここが決まれば他は付いてくる。要件を具体的に固定する。

- 1画面1問。スクロールなしで問題文と4択が収まること
  - 基準は縦向き・標準文字サイズ・幅375px×高さ667px程度の端末。文字拡大時や横向きではスクロールを許容する（WCAG 1.4.10 リフロー、1.3.4 表示の向きを優先）
- 選択肢ボタンは親指到達域（画面下部）に配置
- タッチターゲットは最小 44×44 px（WCAGの下限24pxより余裕を持たせる）
- タイマーは既定でオフ。設定で任意にオン
- 問題文は原則2行以内、最大でも3行（基準端末で。字数上限は `data-schema.md` の60字）
- 回答後は選択肢の位置を動かさない（正解を緑、誤選択を赤でその場に表示）
- 正誤は色だけで示さない。アイコンとテキストを併用する
- 解説は要点1〜2文を即表示し、詳細は折りたたみ
- 解説は問題文エリアに差し替えて表示する（下記レイアウト）
- 「次の問題へ」は固定位置に置き、毎回同じ場所にあること
- 次の問題を先読みし、遷移を体感100ms以内にする
- **この画面には投げ銭の導線を含め、回答への集中を妨げるものを一切置かない**

### レイアウト

画面を上下2つの領域に分け、下部領域は回答前後で一切動かさない。

```
回答前                          回答後
┌────────────────┐              ┌────────────────┐
│ 進捗 3/10       │              │ 進捗 3/10       │
│                 │              │ 問題文（縮小）   │
│ 問題文          │   上部領域    │ ✓ 正解！／✗ 不正解│
│                 │  （差し替え）  │ 解説 要点1〜2文  │
│                 │              │ ▼もっと詳しく    │
├────────────────┤              ├────────────────┤
│ [選択肢A]       │              │ [選択肢A]       │
│ [選択肢B]       │   下部領域    │ [選択肢B] ✓正解  │
│ [選択肢C]       │  （位置固定）  │ [選択肢C] ✗選択  │
│ [選択肢D]       │              │ [選択肢D]       │
│ （空き）        │              │ [次の問題へ]     │
└────────────────┘              └────────────────┘
```

- 上部領域：回答前は問題文、回答後は「縮小した問題文＋正誤＋要点解説＋もっと詳しく」に差し替える
- 「もっと詳しく」を開いたときは上部領域の中だけスクロールさせ、下部領域は動かさない
- 「次の問題へ」の場所は回答前から確保しておき、回答後に表示する（出現で選択肢が押し上げられないように）
- 誤答通報リンク（M-11）は上部領域の解説の近くに置く

## 主要フロー

### フロー1：初回訪問（最短で遊ばせる）

```
トップ → 「今すぐ遊ぶ」 → 習熟度1問（スキップ可） → 全ジャンルミックスで出題開始
```

ログイン画面もチュートリアルも挟まない。1問目までのタップ数は2を目標とする。

### フロー2：通常セッション

```
ジャンル・難易度選択
  → 10問出題（各問：回答 → 即時フィードバック → 解説 → 次へ）
  → セッション結果
  → 「間違えた問題を復習」または「もう1セット」
```

### フロー3：復習

```
成績画面 or セッション結果 → 復習開始 → 間違えた問題を優先出題
  → 正解するとLeitnerのボックスが1つ上がる（出題頻度が下がる）
```

### フロー4：読み物からの流入

```
検索エンジン → 解説記事詳細（P-10）
  → 記事末の「この内容をクイズで試す」
  → 関連ジャンルの出題
```

SEO流入をクイズ利用に転換する主導線。記事とクイズ問題をタグで紐付けておくこと。
