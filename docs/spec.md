## 1. 概要

競馬と馬の知識を、解説を読みながら学べる Web クイズ。差別化の核は解説の質で、全問に根拠のある解説を付ける。
ログインなしで遊べ、進捗はブラウザに保存する。広告は載せない。

- 対象: 競馬を見始めた初心者から、血統や記録に詳しいコアファンまで
- スコープ外: ユーザー投稿問題、リアルタイム対戦、外部IP（ウマ娘等）、多言語、広告、馬券の予想、ネイティブアプリ（理由は `requirements.md`）

## 3. 出題画面（P-04 / P-05）

- 1画面1問。縦向き・標準文字サイズの基準端末（375×667程度）でスクロールなしに問題文と4択が収まる。文字拡大時と横向きはスクロールを許容
- 選択肢は画面下部、タッチターゲット 44×44px 以上。回答後も位置を動かさない
- 回答後は問題文エリアを「縮小した問題文＋正誤＋要点解説＋もっと詳しく」に差し替える
- 正誤は色だけで示さない。アイコンとテキストを併用する
- 「次の問題へ」は回答前から場所を確保し、毎回同じ位置に出す
- この画面には投げ銭の導線を含め、回答の妨げになるものを置かない

レイアウト図は `screens.md`。

### ジャンル・難易度選択（P-03）

- 1画面でジャンル（全ジャンル＋7ジャンル）と難易度（簡単・普通・難しい・おまかせ）を選び、「始める」で出題を始める。初期値は全ジャンル×おまかせ。前回の選択は覚えない
- 選んだ条件は URL のクエリで出題画面に渡す: `/play/session?genre=1〜7|all&difficulty=easy|normal|hard|auto`。不正・欠け・複数指定の値は、その項目を全ジャンル・おまかせにする
- 別ジャンルから補充したセットは、出題の前に確認画面で知らせる。出題画面には何も足さない
- セット終了後は結果画面（下記）に進み、そこに「条件を変える」リンク（`/play` へ）がある
- 設計は `superpowers/specs/2026-10-03-genre-difficulty-select-design.md`（本人承認済み・メンター合意待ち）

### セッション結果（P-06）

- セット終了後に表示する。結果画面の集計は保存せず（解答履歴は M-10 のとおり記録する）、リロードすると消える（U-16 と同じ扱い）
- 見出しは「N問中M問正解」、続けて「回答にかかった時間」。所要時間は各問の回答時間（問題を表示してから回答するまで）の合計で、解説を読む時間は含めない
- 間違えた問題を出題順に並べ、問題文・正解の選択肢・要点解説を常時表示する。「もっと詳しく」・誤答通報・自分が選んだ選択肢は出さない。全問正解のときは一覧の代わりに「全問正解！」
- 「もう一度」（同じ条件で新しいセット）と「条件を変える」（`/play` へ）を画面下に固定する
- 復習への導線（spec の機能一覧にない。M-07 は次のセットに混ぜるだけ）・投げ銭リンク（S-09）・結果のシェア（S-02）は置かない
- 設計は `superpowers/specs/2026-10-05-session-result-design.md`（本人承認済み・メンター合意待ち）

## 4. 出題アルゴリズム

1. 直近に出題した30問を除外する
2. 選んだジャンル・難易度で候補を絞る。10問に満たなければ、隣の難易度 → 同じジャンルの全難易度 → 全ジャンルの順に補充する（全ジャンルから補充したことは画面で知らせる）
3. 復習キューの問題を混ぜる（10問中 最大3問。下の「復習」）
4. 候補の中では未出題の問題を先に使い、足りない分だけ出題済みの問題から選ぶ。どちらもランダム
5. 候補が尽きたら、除外した問題を古い順に戻す

- 補充の段は「未出題かどうか」より優先する。選んだ条件からなるべくずらさないため
- 「未出題」は一度も回答していない問題。「直近30問」は回答履歴を新しい順にたどって集めた、重複しない問題ID 30個
- おまかせ: そのジャンルの easy 3／normal 4／hard 3 問。易しい順に出し、同じ難易度の中はランダム。足りない難易度の分は同じジャンルの他の難易度で埋める
- セット途中でリロード・離脱したら、そのセットは破棄する。回答は1問ごとに保存する

U-12・U-16・U-20 は 2026-10-03 に本人が決定（メンター合意待ち）。設計は `superpowers/specs/2026-10-03-session-algorithm-design.md`。

### 復習（M-07、U-13）

2026-10-08 に本人が決定（メンター合意待ち）。設計は `superpowers/specs/2026-10-08-review-design.md`。

- 2箱。不正解でどの箱からでも箱1に入る。箱1で正解すると箱2、箱2で正解すると卒業（キューから外れる）
- 箱1は次のセットから候補になる。箱2は、最後に正解してからほかの問題への回答が30回に達したあとで候補に戻る（回答数で数える。同じ問題への回答も1回と数える）
- 復習問題は、選んだジャンルの中からだけ混ぜる（全ジャンルのときは全問題）。難易度では絞らない
- 直近30問の除外を受けない。箱1を先に、足りなければ箱2から、同じ箱の中はランダム。最大3問
- おまかせの配分（easy 3／normal 4／hard 3）には復習問題も数える
- 復習の状態は保存せず、回答履歴から計算する（`data-schema.md`）
- 結果画面の導線と復習専用画面（P-07）は機能一覧にないため作らない

## 5. データ

- 問題データの原本は `data/questions/*.json`、型は `lib/types.ts`。配信用はビルド時に生成し、`source`・`status`・`reviewNote` と未公開問題を含めない
- AIが下書きした問題は `draft`・`source` 空欄で入れ、人間が一次情報で確認するまで公開されない（`lib/quiz/validate.ts` が強制）
- 進捗は IndexedDB に保存し、失敗しても画面を壊さない

スキーマの詳細は `data-schema.md`、問題制作のルールは `content-rules.md`。
