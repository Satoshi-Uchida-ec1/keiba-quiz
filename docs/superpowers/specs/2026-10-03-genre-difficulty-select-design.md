## 4. 選択画面

- ジャンル8択（7ジャンル＋全ジャンル）と難易度4択（簡単・普通・難しい・おまかせ）を、それぞれ `fieldset`／`legend` 付きのラジオボタンにする
- ラベルは `GENRE_LABELS`・`DIFFICULTY_LABELS` を使う。全ジャンルは「全ジャンル」、おまかせは「おまかせ」
- 選択状態は色だけで示さない（チェック表示と文字を併用）。タッチターゲットは 44×44px 以上
- 「始める」は通常のリンク（`/play/session?genre=…&difficulty=…`）。投げ銭など回答に関係ないものは置かない
- 画面が縦に収まらない場合はスクロールを許容する（P-04 のような固定は求めない）

## 5. 条件の読み書き

- URL の形: `genre` は `1`〜`7` または `all`、`difficulty` は `easy`／`normal`／`hard`／`auto`
- `parseSetRequest`: 値が範囲外・不正・欠け・複数指定のときは、その項目を「全ジャンル」「おまかせ」にする（項目ごとに判断する）
- `toQuery`: `SetRequest` から `genre=…&difficulty=…` を作る

## 6. 出題画面の流れ

1. URL から `SetRequest` を作り、問題の読み込みと進捗の読み込みを並行して行い、`buildSet` を呼ぶ（今と同じ）
2. 0問なら「公開中の問題はまだありません」（今と同じ）
3. `usedOtherGenres` が true なら、確認画面を出す: 「このジャンルの問題が足りないため、他のジャンルからも出題します」＋「始める」
4. 出題 → 終了。終了画面は「もう一度」（同じ条件で新しいセット）と「条件を変える」（`/play` へのリンク）

## 8. ブラウザでの確認（375×667 を含む）

1. `/play` の初期値が「全ジャンル × おまかせ」で、そのまま「始める」で出題が始まる
2. ジャンル・難易度を変えると、その条件の問題が出る（下書きは easy 5・normal 5）
3. 下書きにないジャンルを選ぶと、補充の確認画面が出て、「始める」で出題に進む
4. `/play/session` に不正なクエリで直接アクセスしても、初期値で始まる
5. 終了後の「もう一度」が同じ条件で始まり、「条件を変える」で `/play` に戻る
6. キーボードだけで、選択から開始まで操作できる
7. `npm run build` が通り、`/play/session` が静的に生成される
