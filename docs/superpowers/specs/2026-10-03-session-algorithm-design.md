## 4. セット生成 `buildSet`

**入力**
- `pool`: 配信中の問題すべて
- `request`: `{ genre: GenreId | "all", difficulty: Difficulty | "auto" }`
- `progress`: 回答したことのある問題IDの集合、直近30問（古い順）
- `random`: `() => number`。テストでは固定した値を返す関数に差し替える

**出力**: `{ questions: DeliveredQuestion[]（最大10問）, usedOtherGenres: boolean }`

### 4.1 候補の段（上の段ほど優先）

| 段 | 難易度を指定したとき（例: ジャンル1×easy） | おまかせのとき |
| --- | --- | --- |
| 1 | ジャンル1×easy | ジャンル1の各難易度から 3／4／3 問ずつ（難易度ごとに選ぶ） |
| 2 | 隣の難易度（easy・hard → normal、normal → easy と hard） | ジャンル1の残りの問題（足りない難易度の分を他の難易度で埋める） |
| 3 | ジャンル1の残りの難易度（easy → hard、hard → easy、normal → なし） | ― |
| 4 | 他のジャンルすべて（`usedOtherGenres = true`） | 他のジャンルすべて（`usedOtherGenres = true`） |

`genre: "all"` のときは「ジャンル1」を全ジャンルと読み替え、段4はない。

### 4.2 選び方

1. 直近30問を除いた候補から、段の順に取る。各段の中では**未出題 → 出題済み**の順に、それぞれランダムで取る
2. 全段を使っても10問に満たなければ、直近30問のうち `pool` にある問題を**古い順に**足す
3. `pool` が10問未満なら、その数だけのセットにする（0問なら空）
4. セットの中で同じ問題は出さない

段の優先は「未出題かどうか」より上に置く。選んだ条件の中に「解いたことはあるが直近30問ではない問題」があれば、隣の難易度の未出題の問題よりそちらを先に出す。選んだ条件からなるべくずらさないため。

### 4.3 並び順

- おまかせ: easy → normal → hard。同じ難易度の中はランダム
- 難易度を指定したとき: 全部ランダム
- 選択肢のシャッフルは既存の `prepareQuestion` を使う

### 4.4 用語

- **未出題**: 一度も回答していない問題。表示しただけで回答しないまま離脱した問題は未出題のまま
- **直近30問**: 回答履歴を新しい順にたどって集めた、重複しない問題ID 30個。data-schema の `seenRecently` は別に保存せず、履歴から計算する（保存が1か所で済み、2か所の内容が食い違うことがない）

## 5. 保存 `lib/progress/`

```ts
interface ProgressStore {
  load(): Promise<Progress>;
  recordAnswer(record: AnswerRecord): Promise<void>;
}
// AnswerRecord = { questionId, correct, answeredAt (ISO 8601), durationMs }
// Progress = { answeredIds: ReadonlySet<string>, recentIds: readonly string[] }
```

- `durationMs` は、問題を表示してから回答するまでの時間（M-06・M-09 で使う）
- IndexedDB: DB 名 `keiba-quiz`、バージョン 1、ストアは `answers` だけ（自動採番のキーと `answeredAt` のインデックス）。他のストアは、使う機能を作るときにバージョンを上げて足す
- メモリ実装: テストに使うほか、IndexedDB が使えないときの代わりにする

### 5.1 エラー時の扱い（CLAUDE.md ルール5）

| 状況 | 振る舞い |
| --- | --- |
| DB を開けない（プライベートモード、非対応など） | メモリ実装に切り替える。直近30問の除外はそのタブの中だけで効く |
| `load` が失敗 | 進捗なし（全問未出題）として出題する |
| `recordAnswer` が失敗 | エラーを握りつぶし、クイズを続ける |
| 問題データから消えたIDが履歴に残っている | 候補に出てこないだけ。特別な処理はしない（data-schema の「欠番は無視」） |

保存できていないことを画面で知らせるかは仕様にないので作らない。worklog の `[要確認]` に書く。
