| # | 決定 | 理由 |
| --- | --- | --- |
| U-13① | 2箱。間違えた問題は箱1に入る。箱1で正解すると箱2、箱2で正解すると卒業（キューから外れる）。不正解は、どの箱からでも箱1に戻る | 仕組みが小さくテストしやすい。features.md の「Leitner方式の軽量版」に合う。3箱は、問題が少ない（今は下書き10問）うちは上の箱に届く前に問題が尽きる。箱なし（正解するまで毎回）は、screens.md の「出題頻度が下がる」を満たさない |

| — | 復習の状態は保存せず、回答履歴から毎回計算する | `seenRecently` と同じ。保存場所を `answers` の1か所にして食い違いを防ぐ。DB の移行が要らない。ルールを後で変えても過去の履歴に適用できる。弱点は回答のたびに全履歴をたどることだが、今の規模では問題にならない。問題が出たら別ストアに切り替える |
| — | 作るのは「次のセットに最大3問混ぜる」まで | spec の M-07 の文言どおり。結果画面の導線と復習専用画面（P-07）は spec の機能一覧にない（§5） |

## 3. 箱の計算 `lib/progress/review.ts`

回答履歴（古い順）を先頭から順にたどり、問題ごとに状態を動かす。

| 回答 | いまの状態 | 次の状態 |
| --- | --- | --- |
| 不正解 | 何でも | 箱1 |
| 正解 | 箱1 | 箱2（この回答の位置を覚える） |
| 正解 | 箱2 | 卒業 |
| 正解 | キュー外（一度も間違えていない・卒業済み） | 変化なし |

最後まで読んだあとの候補:

- 箱1は常に候補
- 箱2は、最後に正解した回答より後の回答数が `REVIEW_INTERVAL`（30）以上のときだけ `box2` に入れる。箱2の問題が最後の正解のあとに自分で回答されると状態が変わるので、あとの回答はすべてほかの問題。数え方は `records.length - 1 - 最後の正解の位置` で済む

```ts
export const REVIEW_INTERVAL = 30;

/** records は古い順。箱1と箱2を分けて返す。箱の中の順は決めない */
export function computeReviewCandidates(records: readonly AnswerRecord[]): ReviewCandidates;
```

`lib/types.ts` に追加:

```ts
/** 復習の候補。箱の中の順は決めない */
export interface ReviewCandidates {
  box1: readonly string[];
  box2: readonly string[];
}
```

`Progress` に `review: ReviewCandidates` を足す。箱を分けて持つのは、出題側が「箱1を先に、同じ箱の中はランダム」で選ぶのに境目が要るため（1本の配列にすると境目が分からない）。

`summarizeAnswers` が `computeReviewCandidates(records)` を呼んで入れる。`ProgressStore` の形、IndexedDB、メモリストアは変えない。読み込みに失敗したときは既存の `summarizeAnswers([])` になり、復習なしで出題が続く（CLAUDE.md ルール5）。

`REVIEW_INTERVAL` は `RECENT_LIMIT`（30）と同じ値だが、別の意味なので別の定数にする。

## 4. 出題への混ぜ方 `lib/quiz/session.ts`

`buildSet` の最初に、復習問題を選ぶ段を足す（spec §4 の手順3）。

1. 候補: `progress.review`（`box1`・`box2`）のうち、`pool` にあり、選択ジャンルに合うもの（`genre === "all"` なら全部）。`pool` にない ID（削除・非公開・欠番）は無視する
2. 直近30問の除外（手順1）を受けない。間違えた問題は直近30問に入っており、除外すると復習が戻れない
3. 選び方: 箱1を先に、足りなければ箱2から、最大 `REVIEW_MAX`（3）問。同じ箱の中はランダム（`RandomSource` を使う）
4. 難易度では絞らない。復習は「間違えた」ことが理由なので、選んだ難易度とは関係なく混ぜる
5. 残りの枠は、今までの段（補充の順・未出題を先に）で埋める。復習で選んだ問題は重複させない
6. おまかせ（`auto`）の配分（easy 3／normal 4／hard 3）には復習問題も数える。その難易度の枠の分だけ、新規の枠を減らす。数えないと、復習が入るたびに最後の枠が削られて偏る
7. 並びは既存の `arrange`（おまかせは易しい順、ほかはランダム）にそのまま入れる。出題画面には復習かどうかを示さない

「次のセットから」は、セットを最初に作る構造から成り立つ。同じセット内で間違えた問題は、そのセットには戻らない。

## 6. テスト

`lib/progress/review.test.ts`:

- 不正解で箱1になる
- 箱1で正解すると箱2、もう一度正解すると卒業
- 箱2で不正解だと箱1に戻る
- 一度も間違えていない問題は候補に出ない
- 卒業後にまた間違えると箱1に戻る
- 箱2は、最後の正解からちょうど30回答後に候補に入り、29回答後は入らない
- 箱1と箱2を別々に返す
- 同じ問題を続けて間違えても、箱1に1回だけ入る

`lib/quiz/session.review.test.ts`（新規。既存の `session.test.ts` は型を合わせるだけにして、復習のテストは別ファイルに置く）:

- 復習は最大3問
- 箱1が箱2より優先される
- 選択ジャンル外の復習問題は混ざらない。全ジャンルのときは混ざる
- 直近30問に入っている復習問題も出る
- `pool` にない ID は無視される
- 復習問題が重複して出ない
- おまかせで、復習問題がその難易度の枠に数えられる
- 復習がないときの出題は今までと変わらない（既存テストが通ること）

同じファイルに、履歴から出題までをつなぐテストを置く。メモリストアに回答を記録し、`load()` して `buildSet` を呼ぶ流れで、次を確かめる:

- 間違えた問題が次のセットに入る
- 正解して箱2に移ると、最後の正解から29回答後までは入らず、30回答後に入る
- もう一度正解すると卒業し、入らなくなる
- 卒業後にまた間違えると、また入る

`lib/progress/summarize.test.ts`（追記）: `review` が履歴から入る。

コンポーネントのテストは作らない（Vitest は node 環境で DOM がなく、新しい依存パッケージも入れない）。

## 7. ブラウザでの確認（375×667 を含む）

下書き10問（easy 5・normal 5）では、1セット10問が常に全問題になる。復習が入っても出題の内容が変わらないので、**ブラウザでは復習の混ざり方を確認できない**。混ざり方は §6 の単体テストと、履歴から出題までをつなぐテストで確かめる。ブラウザでは、変更で画面や出題が壊れていないことだけを確認する（確認できない範囲は worklog に書く）。

1. 全問を回答して結果画面まで進める。間違えた問題があっても、「もう一度」で新しいセットが始まる
2. 画面に変化がない（復習の表示がない）
3. 375×667 で横スクロールなし
4. コンソールエラーなし。`npm run build` が通る

復習が実際に混ざる様子をブラウザで見るには、11問以上の問題が要る（問題制作の進み次第）。
