# 技術要件・非機能要件

## 技術構成

| 層 | 選択 | 理由 |
| --- | --- | --- |
| フロントエンド | Next.js (App Router) / TypeScript | 解説記事をSSGで静的生成でき、クイズ部分はクライアント動作にできる |
| スタイル | Tailwind CSS | |
| 問題データ | 静的JSON + CDN配信 | 問題数が数千規模まではDB不要。低コスト・高速・運用が楽 |
| 進捗保存 | IndexedDB（本体）+ localStorage（設定値） | アカウント不要で始められる |
| ホスティング | Vercel | 個人開発で無料枠に収まる。CDNが標準 |
| 記事管理 | Markdownファイル | CMS不要。Gitで履歴管理できる |

### 重要な設計判断：SPA単体にしないこと

クイズ部分だけを純粋なSPAにしてはならない。解説記事は静的HTMLとして生成し、
クローラーがテキストを読める状態にする。

SPAのみの構成は、AdSense審査で「コンテンツ不足」と判定される典型パターンにはまる。
理由の詳細は `ads.md` を参照。

## パフォーマンス

- 初回表示（LCP）2.5秒以内
- 問題間の遷移は体感で即時（100ms以内）。次の問題を先読みしておく
- 問題データはジャンル単位で分割ロードし、初回に全問取得しない

## アクセシビリティ

WCAG 2.2 レベルAA を目標とする。特に以下を満たす。

| 達成基準 | 内容 | 本アプリでの対応 |
| --- | --- | --- |
| 1.4.1 色の使用 | 色だけで情報を伝えない | 正誤は色＋アイコン＋テキストで示す |
| 1.4.2 音声の制御 | 3秒以上の自動再生音には停止手段が必要 | 音は自動再生しない。デフォルトOFF |
| 1.4.10 リフロー | 横スクロールなしで表示 | レスポンシブ対応 |
| 1.4.11 非テキストのコントラスト | UI部品は3:1以上 | 選択肢ボタンの枠線・状態色 |
| 1.3.4 表示の向き | 縦横どちらでも使える | 向きを固定しない |
| 2.5.1 ポインタのジェスチャ | 単一タップの代替を用意 | スワイプ必須の操作を作らない |
| 2.5.8 ターゲットのサイズ | 最小24×24 px | 選択肢ボタンは44×44 px以上 |

1.4.1 は特に重要。正誤を緑と赤だけで示すと、色覚特性のあるユーザーが判別できない。

## ブラウザ対応

- 最新版の Chrome / Safari / Firefox / Edge
- iOS Safari と Android Chrome を主要ターゲットとする
- IE は対象外

## オフライン対応（フェーズ2）

Service Worker で問題データと主要アセットをキャッシュする。
静的JSON構成はキャッシュとの相性が良い。

「オフラインで使えない」は既存クイズアプリへの典型的な不満なので、実装コストが低いうちに
対応しておく価値がある。

## 運用・品質

- 全問題に `source` を持たせ、通報があったときに一次情報まで遡れるようにする
- 誤答通報が同一問題に複数件ついたら即レビュー
- 問題の修正履歴を残す（Gitで管理すれば自動的に満たせる）
- 時事フラグ付き問題の年次レビュー
- 実測正答率が想定レンジから大きく外れる問題は、難易度タグを修正する
