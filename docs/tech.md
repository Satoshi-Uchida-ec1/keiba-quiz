# 技術要件・非機能要件

## 技術構成

| 層 | 選択 | 理由 |
| --- | --- | --- |
| フロントエンド | Next.js (App Router) / TypeScript、静的出力（`output: 'export'`） | 解説記事をSSGで静的生成でき、クイズ部分はクライアント動作にできる。静的ファイルのみなのでホスティングを移しやすい |
| スタイル | Tailwind CSS | |
| 問題データ | 静的JSON + CDN配信 | 問題数が数千規模まではDB不要。低コスト・高速・運用が楽。配信用JSONはビルド時に原本から生成（`data-schema.md`） |
| 誤答通報 | Googleフォームへの通常リンク | サーバーを持たずに通報を受け取れる。クリックするまで外部送信が発生しない |
| 進捗保存 | IndexedDB（本体）+ localStorage（設定値） | アカウント不要で始められる |
| ホスティング | Vercel（Hobby） | 個人開発で無料枠に収まる。CDNが標準。**投げ銭公開前に規約を再確認**（後述） |
| 記事管理 | Markdownファイル | CMS不要。Gitで履歴管理できる |

### 重要な設計判断：SPA単体にしないこと

クイズ部分だけを純粋なSPAにしてはならない。解説記事は静的HTMLとして生成し、
クローラーがテキストを読める状態にする。

SPAのみの構成は、検索エンジンからはテキストの乏しいページに見え、検索流入を得られない。
解説記事から流入してクイズに進む導線（`screens.md` フロー4）が成立しなくなる。

### ホスティングの規約上の制約

Vercel の Hobby（無料）プランは非商用の個人利用に限られる。投げ銭が商用利用に含まれるかは
ドキュメントの版によって記載が食い違っているため、投げ銭リンクの公開前に再確認する。
詳細と対応方針は `monetization.md` を参照。

移行の可能性に備え、`output: 'export'` による静的出力とする。これにより次の機能は使わない。

- Request に依存する Route Handlers、Server Actions、Proxy（旧ミドルウェア）
- cookies の読み取り、next.config の rewrites / redirects / headers
- `generateStaticParams()` のない動的ルート（解説記事ページは `generateStaticParams()` で全件生成する）
- ISR、Draft Mode
- `next/image` の既定ローダーによる画像最適化（MVPは写真を使わないので影響は小さい）

詳細は `node_modules/next/dist/docs/01-app/02-guides/static-exports.md` の Unsupported Features。

## パフォーマンス

- 初回表示（LCP）2.5秒以内
- 問題間の遷移は体感で即時（100ms以内）。次の問題を先読みしておく
- 問題データはジャンル単位で分割ロードし、初回に全問取得しない

## アクセシビリティ

WCAG 2.2 レベルAA を目標とする。特に以下を満たす。

| 達成基準 | 内容 | 本アプリでの対応 |
| --- | --- | --- |
| 1.4.1 色の使用 | 色だけで情報を伝えない | 正誤は色＋アイコン＋テキストで示す |
| 1.4.2 音声の制御 | 3秒以上の自動再生音には停止手段が必要 | 音は自動再生しない。デフォルトOFF |
| 1.4.10 リフロー | 横スクロールなしで表示 | レスポンシブ対応 |
| 1.4.11 非テキストのコントラスト | UI部品は3:1以上 | 選択肢ボタンの枠線・状態色 |
| 1.3.4 表示の向き | 縦横どちらでも使える | 向きを固定しない |
| 2.5.1 ポインタのジェスチャ | 単一タップの代替を用意 | スワイプ必須の操作を作らない |
| 2.5.8 ターゲットのサイズ | 最小24×24 px | 選択肢ボタンは44×44 px以上 |

1.4.1 は特に重要。正誤を緑と赤だけで示すと、色覚特性のあるユーザーが判別できない。

## ブラウザ対応

- 最新版の Chrome / Safari / Firefox / Edge
- iOS Safari と Android Chrome を主要ターゲットとする
- IE は対象外

## オフライン対応（フェーズ2）

Service Worker で問題データと主要アセットをキャッシュする。
静的JSON構成はキャッシュとの相性が良い。

「オフラインで使えない」は既存クイズアプリへの典型的な不満なので、実装コストが低いうちに
対応しておく価値がある。

## 運用・品質

- 全問題に `source` を持たせ、通報があったときに一次情報まで遡れるようにする
- 誤答通報が同一問題に複数件ついたら即レビュー
- 問題の修正履歴を残す（Gitで管理すれば自動的に満たせる）
- 時事フラグ付き問題の年次レビュー
- 実測正答率が想定レンジから大きく外れる問題は、難易度タグを修正する
